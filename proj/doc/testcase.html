Test cases

In this project, a test case is a single, simple, undirected, unweighted graph G = (V, E). A graph is represented by:

  • n — the number of vertices (labeled 0, 1, …, n−1),
  • edges — a list of vertex pairs {u, v}, each representing one undirected edge,
  • graphName — a human-readable name of the graph (e.g. "Petersen", "Zachary Karate", "G(100,0.4)"), used for identification in result tables and graphs.

For Java programs, the test case input is declared as: 

public class Input extends AbstractInput {
  public int n;
  public int[][] edges;
  public String graphName;
}

Algorithm output

The goal of each algorithm is to compute a valid coloring of the input graph, i.e. an assignment of a positive integer color to every vertex such that no two adjacent vertices share the same color: 

public class Output extends AbstractOutput {
  public int[] color;   // color[v] is the color assigned to vertex v
}

Test of correctness

Unlike problems such as sorting, the Graph Coloring Problem does not have a single correct output: many valid colorings exist for the same graph, often using different numbers of colors. For this reason, correctness is not checked by comparing the algorithm's output against one fixed expected output. Instead, the produced coloring is re-validated directly against the input graph:

  • every vertex must be assigned a positive color, and
  • for every edge {u, v} ∈ E, it must hold that color(u) ≠ color(v).

This check is implemented by the Check indicator, which reports OK if the coloring is valid and NOK otherwise. The quality of a (valid) coloring is then measured by the separate NumColors indicator — the number of distinct colors used. Lower values indicate a better, more efficient coloring (closer to the graph's true chromatic number χ(G)).
